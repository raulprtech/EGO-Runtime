# G1.13 — deterministic ARIA decision feedback

Date: 2026-08-15.

## Outcome

EGO and ARIA now have a deterministic feedback path for future approvals
recorded through the Hermes decision sidecar. After Nigma accepts the exact
authenticated human turn, EGO atomically stores a sealed informational event.
ARIA's existing `/api/aria/events` polling channel retrieves it and presents:

> Aprobación registrada — Nigma registró tu aprobación. La ejecución no
> comenzó; requiere un paso separado.

This receipt is not generated by Hermes or an LLM. It therefore remains correct
even if the assistant text claims that Nigma is unavailable or that the action
could not be completed.

## Authority and privacy boundaries

- `POST /v1/runtime/nigma/conversation-decisions` still requires both the
  runtime credential and the independent human-decision credential.
- A successful decision persists one idempotent `nigma.decision-event/v1` only
  after Nigma returns a verified approval record.
- The event stores only domain-separated profile/conversation hashes, approval
  identities/digests, fixed UI copy and `execution_performed=false`.
- Storage is an owner-only directory with regular `0600` files, atomic rename
  and an integrity digest over the canonical record.
- `GET /v1/runtime/nigma/decision-events?profile=aria` needs only the runtime
  credential and returns a five-field projection. It cannot approve or execute.
- The ARIA relay uses its server-side EGO token for that read. The phone keeps
  only `RELAY_TOKEN`; neither runtime nor human-decision authority reaches the
  mobile client.
- Profiles are filtered by hash. The fixed relay profile prevents the app from
  becoming a profile/session selector.

## Errors and decisions retained

The first filesystem patch attempt failed because the environment has no
`bubblewrap`; the approved interactive `apply_patch` path was used. A combined
test patch then failed without changing files because it referenced context
from two different test files; the patches were split and applied cleanly.
GitHub CLI's normal PR editor again queried the removed Projects Classic field
and failed after commits were pushed. The three draft PR bodies/titles were
updated through the REST pull-request endpoint and read back successfully.

Appending a synthetic assistant message to Hermes was rejected as the product
contract: it would blur model output with authority and Hermes exposes no
necessary supported append route in this integration. Adding approval
credentials to ARIA was also rejected. The already implemented event channel
provided the narrowest replaceable boundary.

The prior G1.12 approval is deliberately not backfilled: G1.13 does not invent
an event from partial historical data. New approvals produce receipts at the
time their verified record is returned. No model, external network, VPS, GPU,
Hermes source modification or execution was used.
