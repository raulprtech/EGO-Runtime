# G1.10 — Hermes conversation decision sidecar

Date: 2026-08-15.

## Outcome

EGO now includes a replaceable CLI sidecar that reads an authenticated Hermes
session and calls the neutral G1.9 port only when exactly one new `user` message
equals the sealed approval phrase byte for byte. It snapshots message-identity
hashes before presentation, ignores baseline/model/decorated turns and fails
closed if more than one exact candidate appears.

The binding is canonical, SHA-256 sealed and persisted atomically as `0600`.
It retains only domain-separated phrase, session and message hashes plus sealed
decision evidence. It never stores raw chat text, raw opaque references,
credentials, objective or learning material. After one approval it enters
`recorded`; later scans return locally without contacting Hermes or EGO.

The adapter requires independently held Hermes, EGO runtime and human-decision
credentials. URLs require HTTPS or loopback HTTP and reject embedded
credentials, query strings, fragments and redirects. The adapter records only;
there is no execution call. HermesMobile/ARIA was not modified. Olimpo was not
used because this boundary belongs beside the host runtime, not in deployment.

## Retained failures and repairs

1. The first focused recording test spread the previous `binding_digest` into
   the strict binding core during reseal. The repair removes the old digest
   before constructing and sealing the new recorded core.
2. Sandboxed commands could not start because `bubblewrap` is absent. The local
   integration used the explicitly approved unsandboxed process path.
3. The first CLI attempt found no `node` through the noninteractive shell. The
   test used the already installed Linux Node 22 path; no dependency changed.
4. An initial audit query counted whole fixture tables when they lacked a
   physical `plan_id` column, incorrectly showing historical fixture activity.
   The corrected query scoped JSON payloads to the exact plan ID and established
   one approval with zero execution-side records. Both measurements are retained
   here so the correction is auditable.
5. The first direct documentation patch encountered the same absent
   `bubblewrap`; the approved interactive `apply_patch` path preserved the
   required editing method.
6. A redundant final command requested `npm run build:server`, which is not a
   declared script. No repair was needed: the successful `npm run build`
   already runs both `vite build` and the server `esbuild` bundle.

## Remaining boundary

The sidecar is polling-oriented and validated against Hermes' current message
shape through a strict adapter. Production work still needs deployment-specific
secret injection, service supervision and confirmation against the exact Hermes
version in use. Those changes do not require ARIA modifications and must retain
the separate execution gate.
