# F4.6 — Runtime-neutral host events

Date: 2026-08-14

## Result

EGO 0.9 implements the first live `nigma.host-event/v1` host adapter. The
authenticated `POST /v1/runtime/nigma/host-runs` response retains its F4.5
receipt/result fields and now adds a stable `host_run_id`, protocol version and
eight ordered events from request receipt through Nigma receipt recording.

The host-run identity is derived from the plan and idempotency key through
SHA-256; the raw key is never returned. Events carry only bounded IDs, digests,
versions, statuses and evidence. They contain no route URL, environment-variable
name or credential. Exact replay retains the host-run and receipt identities and
marks `runtime_accepted.replayed=true`.

Nigma's independent Python verifier accepted the live first trace and replay.
The complete cross-process workflow also retained one ExperienceRecord. EGO's
34 tests passed with one intentional skip in 3.00 seconds and TypeScript passed.
An exact no-hardlink clone repeated 34/34 with one skip in 3.19 seconds,
TypeScript and the live loop against an exact Nigma clone using only local
dependency caches.
No external model, network, cloud, GPU, VPS or interface change was used.

## Limits

The endpoint remains synchronous and retains partial progress only in memory for
the duration of a successful request. Existing structured HTTP errors still fail
closed, but durable partial failure traces, asynchronous event retrieval and the
real Hermes bridge remain later gates. HermesMobile/ARIA was not modified.

The detailed development attempts and repairs are recorded in Nigma's
`docs/DEVELOPMENT_LEDGER.md` section 67 and the F4.6 result document.
