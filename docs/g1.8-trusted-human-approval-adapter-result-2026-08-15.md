# G1.8 — trusted human-approval adapter

Date: 2026-08-15.

## Outcome

EGO now accepts an exact external human decision through
`POST /v1/runtime/nigma/human-approvals`. The endpoint requires the normal
runtime bearer credential plus a distinct `NIGMA_HUMAN_DECISION_TOKEN` of at
least 32 characters. Equal runtime/human credentials fail closed.

Each G1.7 projection creates a sealed two-hour challenge in
`LOCAL_DATA_DIR/nigma-human-approval-challenges`. It binds the exact host
preparation, projection ID/digest, phrase SHA-256 and Nigma plan/route/plugin/
provider approval target. It stores no objective, material reference, raw
approval phrase, credential or idempotency key. Atomic files must be mode
`0600`; EGO verifies the final mode and removes an unsafe file before failing.

The submission uses an absolute approval expiry between one minute and two
hours in the future and cannot outlive its challenge. After validating the
persisted challenge, EGO sends Nigma only the exact approval target and sealed
decision evidence. It verifies the complete returned binding and seals
`nigma.trusted-human-approval-record/v1` with
`authority=trusted_human_adapter`, `approval_recorded=true` and
`execution_performed=false`. It never invokes or resumes a runtime.

## Retained failures, decisions and repairs

1. The first design returned the whole preparation from the client. Security
   review rejected this because a caller could manufacture approval context.
   The final design reloads a minimal sealed challenge by preparation ID.
2. A duration-relative approval expiry changed between retries and broke exact
   idempotency. The request now carries one stable absolute `expires_at`.
3. The first storage test used the Windows-mounted temporary directory. DrvFS
   reported mode `0777` even after `chmod`. EGO now verifies mode and fails
   closed; tests and secure local operation use Linux `/tmp` or another
   owner-permission-capable filesystem.
4. Two early synthetic challenge files reached the repository-local ignored
   data directory before test isolation was corrected. They were moved
   recoverably to `/tmp/ego-g18-test-challenges-from-repo-20260815`; current
   fixtures use distinct Linux temporary directories and clean them.
5. The repository has no `npm run typecheck` script. That command failed only
   at the script lookup; the intended `npx tsc --noEmit` check passed.
6. `jq` was unavailable during the real checkpoint. The malformed piped request
   returned 400 and changed no state; a Node JSON producer then completed the
   same test without adding a dependency.
7. Reading the API key from the already running Nigma process was rejected as
   unsafe credential probing. The real checkpoint instead used a copied
   synthetic database and fresh isolated credentials.
8. Review found G1.7's digest response header was set but absent from the CORS
   exposed-header list. `X-Nigma-Projection-Digest` is now browser-readable for
   configured origins.

## Remaining gate

Positive transport is covered against a strict mock Nigma endpoint, including
exact payload, upstream response verification, restart recovery and identical
replay. A real control-plane approval remains deliberately pending until an
owner explicitly submits the exact phrase. Execution is a later, separately
authorized operation.
