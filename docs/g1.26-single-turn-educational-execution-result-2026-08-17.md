# G1.26 — Ejecución educativa inmediata y consistencia de idioma

Fecha: 2026-08-17

## Resultado

ARIA puede enviar un documento y una instrucción educativa en un único turno. El relay prepara el trabajo mediante EGO/Nigma, enlaza la instrucción original autenticada con la preparación sellada y solicita su ejecución sin presentar una confirmación redundante. El resultado verificado vuelve como Markdown en ese mismo turno.

Esta autoridad sólo aplica a preparaciones de riesgo bajo o medio, lectura local y la capacidad ya permitida `educational_execution`. No autoriza cuentas externas, red, publicación, compras, efectos destructivos ni nuevas capacidades. El endpoint anterior de confirmación explícita permanece disponible para otros clientes.

## Controles

- La instrucción ejecutada debe ser byte-equivalente al objetivo sellado mediante SHA-256.
- El turno debe declarar rol `user` y origen humano autenticado.
- Los identificadores de preparación y proyección y su digest deben coincidir y no estar vencidos.
- Aprobación y ejecución conservan identidades idempotentes y pasan por el mismo plan exacto de Nigma.
- ARIA sólo acepta un resultado exitoso con el contrato `nigma.authenticated-educational-request-execution-record/v1`.
- El artefacto se vuelve a verificar antes de proyectarlo; las referencias privadas e identificadores internos no se muestran.

## Idioma

El proveedor determinista detecta el idioma del objetivo y genera todos los campos visibles del plan en español cuando corresponde. El contrato del planificador exige al resto de proveedores conservar el idioma del objetivo. Esta detección es una heurística acotada del modo demostración, no identificación lingüística general.

## Evidencia

- EGO: 78 pruebas aprobadas y 1 omitida; `tsc --noEmit` aprobado.
- ARIA: 77 pruebas aprobadas; `tsc --noEmit` aprobado.
- Smoke real: `single_turn=true`, `executed=true`, `spanish_only=true`, referencias privadas suprimidas y nombres internos suprimidos.
- Modelo activo: `deterministic-demo`; no se usó un modelo remoto.

## Fallos y reparaciones

La primera ejecución real devolvió 502. El diagnóstico saneado mostró que EGO devolvía 404 porque el proceso activo todavía cargaba el código anterior. Se reinició EGO, se retiró la instrumentación temporal y el smoke pasó. Las primeras pruebas de ARIA también esperaban el protocolo anterior de dos turnos; se actualizaron para exigir exactamente tres saltos internos —preparar, ejecutar y presentar— dentro de un único turno del usuario.

No se inventó medición HIE y no se amplió la allowlist.
