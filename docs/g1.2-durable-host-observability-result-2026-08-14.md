# G1.2 — Durable host observability

Date: 2026-08-14 (America/Mexico_City)

## Outcome

EGO now persists the host-neutral Nigma lifecycle before each external
transition and exposes authenticated state and cursor-based event reads. A
completed or partial host run remains inspectable after the EGO process is
restarted. This change does not modify ARIA, grant approval authority to EGO,
install a model, use a VPS or add an external dependency.

The durable contract is `nigma.host-run-record/v1`. Each record contains the
stable host/plan identities, SHA-256 request and idempotency digests, status,
ordered events, content-free artifact references, optional terminal result and
a bounded sanitized error. It deliberately excludes the idempotency key,
learner identifiers, input material content, endpoints, environment-variable
names and credentials.

## Interfaces

- `GET /v1/runtime/nigma/host-runs/:host_run_id` returns the sealed record.
- `GET /v1/runtime/nigma/host-runs/:host_run_id/events?after=N` returns
  `nigma.host-event-page/v1`, the current status and a resumable cursor.
- The existing synchronous `POST /v1/runtime/nigma/host-runs` remains
  compatible and now persists every event, artifact discovery, terminal result
  and failure.

Records are atomically replaced under
`LOCAL_DATA_DIR/nigma-host-runs/<host_run_id>.json`. The directory is mode
`0700`, files are mode `0600`, writes use a unique temporary file plus rename,
and reads validate both the strict schema and `record_digest`. Host IDs are
restricted to `host-` plus 32 lowercase hexadecimal characters before path
resolution.

## Decisions

1. Keep the runtime transport synchronous for this local milestone; add durable
   observation without claiming a restartable distributed scheduler.
2. Preserve exact retries as separate numbered attempts instead of silently
   replacing prior evidence.
3. Coalesce simultaneous identical in-process requests. Reject changed learner
   context under the same plan/idempotency identity before upstream contact.
4. Persist references and hashes, never artifact bodies or learner context.
5. Treat a corrupted record as an integrity failure, not as missing state and
   not as a record that can be silently repaired.

## Attempts, failures and repairs

- Reusing the prior G1.1 plan for the first real attempt reached execution but
  Nigma rejected the new receipt as `runtime_receipt_conflict`. G1.2 retained
  that partial failure instead of losing it. A fresh synthetic plan removed the
  stale receipt identity and completed.
- Restart recovery also encountered an older pending job whose README reference
  no longer matched its captured byte size. Artifact validation failed closed
  with `Artifact size mismatch`; the new G1.2 golden was unaffected. This is
  evidence for a later stale-input recovery policy, not a reason to weaken hash
  or size validation.
- The workspace sandbox could not start because `bubblewrap` was unavailable.
  Existing files therefore could not be edited with `apply_patch`; patches were
  staged in `/tmp` and applied with bounded `git apply --recount`. One initial
  hand-counted patch was rejected as corrupt before any source change; using
  recount repaired the workflow.
- A diagnostic configuration read printed an existing provider credential into
  the tool transcript. The credential was not used: subsequent process tests
  used `env -i` and `MODEL_PROVIDER=deterministic-demo`. The exposed credential
  must be rotated/revoked; no credential value is retained in this document or
  in the G1.2 host records.

## Remaining boundary

G1.2 does not yet provide background dispatch, a durable coordinator lease or
automatic continuation from the exact interrupted transition. A crash during
an active synchronous request requires an exact idempotent retry. That
scheduler/recovery work is the natural next package; ARIA can consume these
neutral reads later without becoming part of Nigma's authority boundary.
