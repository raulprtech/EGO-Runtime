# G1.3 runtime competition fallback

EGO now turns a sealed pre-acceptance host failure into a bounded request for a
new Nigma plan. `POST /v1/runtime/nigma/host-runs/:host_run_id/fallbacks`
accepts no caller body, requires authentication and idempotency, reads the G1.2
record and derives one of `runtime_unreachable`, `runtime_unavailable` or
`runtime_rejected`. Any `runtime_accepted` event makes fallback ineligible.

The returned `nigma.host-fallback-preparation/v1` verifies the source
invocation and record digest, the failed runtime, every replacement
plan/runtime/plugin/provider/route link and the fixed no-authority flags. EGO
does not approve, select a replacement itself or execute during preparation.

The isolated cross-process golden selected declared Hermes 0.20, routed it to a
deliberately unreachable loopback address and retained three events plus error
digest `7c1805b66b02c0cea2f38f2ec390ae837a39d8bd261dda4e75a6a298ee26b931`.
Nigma returned fallback `runtime-fallback-b359527eddee9762` with a new EGO
plan. Execution was blocked before a separate synthetic approval, then EGO
completed eight events and four independently hash-verified artifacts as host
run `host-84110927b83587ba7c26edfc33929559`. Both the failed and successful
records survived an actual EGO restart.

Tests cover the valid pre-acceptance failure, caller-body rejection, exact
evidence projection and refusal after acceptance/timeout. The EGO suite passes
42 tests with one intentional cloud skip; TypeScript and both production builds
pass. No model, external network, ARIA, cloud, GPU or VPS was used. The Hermes
entry is a declared adapter candidate, not a complete Hermes executor claim.

During development Nigma initially admitted Hermes globally, which broke
historical EGO-specific routes; the control plane repaired this with an
educational feature gate. `jq` and `bubblewrap` were absent, so authenticated
read APIs and approved patch sessions were used instead.
