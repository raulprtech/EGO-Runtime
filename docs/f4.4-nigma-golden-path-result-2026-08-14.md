# F4.4 — Nigma to EGO local golden path

Date: 2026-08-14

## Outcome

EGO 0.7.0 now consumes Nigma's exact F4.3 route through an authenticated, disabled-by-default HTTP adapter. A runtime-owned policy allowlists exact plugin/provider hashes, bindings, permissions, output types and URI schemes. The adapter maps approved references into the existing learning workflow and returns a `RuntimeExecutionReceiptCreate` accepted by Nigma's F3 conformance contract.

The golden test reads a real local Markdown source, uses the credential-free deterministic demo provider, runs document analysis, planning, practice and mastery initialization, writes four hashed artifacts, verifies idempotent replay and rejects learner-context substitution.

## Safety properties

- No plugin code is installed or dynamically imported from Nigma.
- No endpoint, credential or private provider configuration enters Nigma.
- Unknown fields, duplicate policy identities and partial hash pairs fail closed.
- Nested binding hashes must equal selected snapshot hashes even if an attacker recomputes the outer invocation digest.
- Route permissions must be present in the invocation and both surfaces must fit the local allowlist.
- Local files still pass realpath confinement under `LOCAL_INPUT_ROOT`.
- A route-bound Nigma approval cannot enter EGO's ordinary approval path accidentally; it uses the separate `/nigma/invocations` endpoint.
- Idempotency covers the mapped learner/session context as well as the Nigma links.
- Receipts fail closed if any artifact lacks a SHA-256 or byte size.

## Evidence

TypeScript compilation passed. EGO-Runtime passed 32/32 tests with 1 intentional skip in 2.84 seconds. Nigma passed 440/440 tests in 41.60 seconds with one pre-existing Starlette/httpx deprecation warning. A no-hardlink local clone of the committed tree also passed TypeScript and 32/32 tests with 1 intentional skip in 2.93 seconds, reusing only the local dependency cache. Cross-language evidence includes a Python-generated invocation accepted by TypeScript and a TypeScript-generated receipt accepted by Nigma.

## Failures and repairs

- Node existed under NVM but was absent from the session `PATH`; direct Node 22 invocations were used without installation.
- The safe patch helper could create new WSL files but could not update existing ones because `bubblewrap` is unavailable.
- Two automatic permission reviews timed out without executing their commands. Smaller, explicit Git patches completed the same scoped edits.
- Several documentation patches were rejected for incorrect hunk counts or Unicode context. Exact scoped substitutions repaired them, and `git diff --check` remained clean.
- Nigma pytest initially inherited Windows `TEMP`/`TMP` and lost its capture file before collection; capture-free execution with a WSL base temp passed 440/440.
- Review found that storing only the Nigma digest as EGO's idempotency key would permit learner-context substitution. EGO now hashes the complete mapped request.
- Closing hardening added policy uniqueness, nested binding digest/version agreement, permission containment, invalid URI encoding handling and complete artifact evidence.

## Deferred

A real Gemini run is not included because no Gemini or Google Cloud credential is configured in the current environment. The deterministic provider proves orchestration and artifact flow, not model quality. Remote deployment, signed Nigma envelopes, ARIA changes and production credential provisioning remain deferred.
