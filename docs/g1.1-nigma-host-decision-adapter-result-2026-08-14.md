# G1.1 — Nigma host decision adapter

Date: 2026-08-14

## Outcome

EGO can now act as a neutral host for the complete two-step Nigma decision boundary:

1. `POST /v1/runtime/nigma/educational-tasks/prepare` submits a bounded educational objective and local file metadata to Nigma.
2. EGO validates every sealed link and returns a compact `nigma.host-preparation/v1` view for human review.
3. EGO does not accept or create an approval. Its response is structurally fixed to `awaiting_human_approval`, `approval_granted=false` and `execution_performed=false`.
4. After an external trusted actor records the exact decision in Nigma, the existing `POST /v1/runtime/nigma/host-runs` resumes. Nigma remains the authority: absent or expired approval fails before any runtime route is loaded or contacted.

This makes Hermes optional for the first educational path. ARIA remains unchanged and can later consume the same host projection through its runtime connection.

## Contract

```http
POST /v1/runtime/nigma/educational-tasks/prepare
Authorization: Bearer <host-token>
Idempotency-Key: <stable-key>
Content-Type: application/json

{
  "objective": "Create a bounded study plan",
  "materials": [{
    "uri": "file:///controlled/course/notes.md",
    "media_type": "text/markdown",
    "schema_ref": "schema://learning-material/v1",
    "sha256": "<sha256>",
    "size_bytes": 512
  }]
}
```

The response exposes only the user objective, plan identity/digest/confidence/risk, selected runtime identity/snapshot, exact approval target, a fixed resume path and content-free evidence references. Full internal component candidates and registry details are not relayed to an interface by default.

## Safety decisions

- Authentication and a bounded `Idempotency-Key` are required before contacting Nigma.
- Materials are restricted to local `file://` references; remote file hosts, credentials, raw contents and undeclared fields are rejected.
- Nigma responses that claim preparation-time approval/execution fail schema validation.
- Plan, runtime, plugin, provider, route and approval-target IDs/digests must agree exactly.
- EGO contains no endpoint that converts the presentation into an approval.
- Resume calls only Nigma's invocation endpoint. Therefore rejected, absent, altered or expired approvals cannot reach an execution runtime.
- Runtime routes and credentials remain operator-owned and are not exposed in the preparation response.

1. The safe patch helper could create new files but could not update existing files because `bubblewrap` was unavailable. Exact temporary diffs were applied with `git apply`; two small edits to the new untracked test used a bounded Perl replacement after `git apply` could not address an untracked path.
2. The first route-import rewrite cut one line too early, producing an incomplete TypeScript import. `tsc --noEmit` detected it immediately; the exact two missing/extra lines were repaired before tests.

## Remaining boundary

G1.1 is synchronous and does not persist partial host-preparation state. It does not upload mobile files, present native UI controls, record real human identity, stream preparation progress or manage login. G1.2 should make execution progress and artifact delivery durable and host-neutral before ARIA integration resumes.
