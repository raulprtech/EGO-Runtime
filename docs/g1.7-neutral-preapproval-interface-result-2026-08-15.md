# G1.7 — neutral pre-approval interface projection

Date: 2026-08-15.

## Outcome

EGO now projects a verified G1.6 host preparation as
`nigma.host-preparation-interface/v1`. The projection is host-owned and
interface-neutral. It contains exactly three generic events already understood
by ARIA's current stream parser:

1. `tool.started` for `nigma.plan`;
2. `tool.completed` for the same `tool_call_id`;
3. `assistant.completed` with the localized human-review text.

The assistant text contains the caller objective, selected-runtime summary,
risk, confidence, advantages, tradeoffs, reason text, disclaimer and the exact
approval phrase. The phrase remains the canonical Spanish machine phrase in
both locales; surrounding instructions are localized. The projection links the
exact host preparation and G1.6 presentation IDs/digests, then receives its own
canonical SHA-256 and content-derived ID.

The projection is fixed to `human_decision_required`,
`approval_recorded=false` and `execution_performed=false`. It contains no
approval-write route and cannot resume execution.

## API behavior

The existing authenticated preparation endpoint remains JSON by default. A
caller that explicitly sends `Accept: text/event-stream` receives the same
three projection events as SSE. The response includes
`X-Nigma-Projection-Digest`, disables intermediary buffering/cache and never
falls back silently when a historical preparation lacks a verified G1.6
presentation.

Locale remains host-only and is stripped before Nigma. JSON and SSE requests
using the same neutral payload and idempotency key therefore refer to the same
Nigma plan.

## Real-process and ARIA-parser evidence

A real Nigma process on port 8000 and an isolated EGO on port 3001 prepared the
current EGO README reference. The JSON and SSE views returned HTTP 200 and the
same projection:

- ID `host-preparation-interface-25331f576bcd1dee`;
- digest `25331f576bcd1deede2f83557fe4dcfae0589624d2b48294391624e42df1509b`;
- event order `tool.started → tool.completed → assistant.completed`;
- exact equality between parsed SSE events and the sealed JSON event array;
- response-header digest equal to the JSON digest;
- independently recomputed canonical digest equal to both.

The unchanged parser imported from `HermesMobile/src/lib/sse.ts` consumed the
stream in 17-character fragments, reconstructed all three events, treated
`assistant.completed` as authoritative replacement text and retained both the
objective and approval phrase. HermesMobile remained read-only and unchanged.

## Validation

- focused preparation/fallback tests: 9/9;
- complete EGO suite: 45/45 plus one intentional cloud skip;
- TypeScript: clean;
- Vite and server production bundles: passed;
- external model, external network, cloud, VPS, GPU and ARIA changes: zero.

## Retained failures and repairs

1. The first TypeScript run followed 9 passing functional tests but inferred
   Zod tuple members as `unknown`. A typed union was added only at the renderer
   boundary; strict schemas and runtime validation were retained.
2. The first real-parser command expected a local `tsx` loader inside
   HermesMobile, where that dependency is intentionally absent. The existing
   EGO loader executed ARIA's real source without installing or changing
   anything.
3. Negotiation review found that SSE headers were set before a historical
   projection could fail. Rendering now occurs first, and media-type matching
   is case-insensitive.
4. `bubblewrap` remains unavailable; approved interactive patches were used.

## Limit

This proves wire compatibility with ARIA's parser, not a physical-device chat
turn or automatic runtime selection from the mobile application. The host or
Hermes adapter still owns conversation routing and must record a real external
human decision through the trusted approval path before execution.
