# EGO G1.19 — portable material staging

## Result

EGO now owns the local learning-material boundary. An authenticated relay can
send binary content to `POST /v1/runtime/materials`; EGO returns a versioned
reference containing material ID, local URI, MIME, SHA-256, size, permission,
hashed owner and sealed record digest. Nigma receives only the reference
metadata through the later preparation flow.

The endpoint accepts PDF, plain text, Markdown and JSON, at most 15 MiB by
default. The name/extension must agree with MIME. Storage must be a strict child
of `LOCAL_INPUT_ROOT`; directories are `0700`, content and manifests `0600`, and
filesystems unable to enforce those modes fail closed. Cloud staging returns
not implemented rather than silently changing locality.

The same owner and idempotency key with identical bytes returns
`already_staged`; changed bytes conflict. Owner mismatch, root escape,
unsupported type, oversized input, record/content tampering and unauthenticated
requests fail. `GET` revalidates bytes after restart. `DELETE` removes content,
updates the record to `released`, and replays the same tombstone on a retry.
Neither staging nor release can approve or execute a Nigma plan.

## Real isolated evidence

Fresh EGO, Nigma and ARIA-relay processes used loopback ports 13119, 18119 and
18787. The relay sent a 65-byte synthetic Spanish Markdown source. EGO stored:

- material `material-796e91a015557288126d7b47b75e4eb0`;
- SHA-256 `dfefd017d3d28d83ad096418ec675040ff77ee6a1c40cd84fa70f66aa6c83a4e`;
- owner-only content under the isolated Linux input root;
- no raw owner value in the durable record.

After an actual EGO restart, authenticated readback returned the identical
active record and verified content. Nigma prepared plan code `AB9D8A` from URI,
MIME, hash and size, while approval, execution and invocation counts remained
zero. Two releases returned one stable tombstone and the source file was absent.
The relay created no Windows/local upload copy. All temporary services stopped.

## Verification and retained failures

- Complete EGO suite: 72 passed, one intentional cloud skip.
- TypeScript, Vite client, Node server and standalone sidecar builds passed.
- Focused cross-repository checks: EGO 13, ARIA 37 and Nigma 14 passed before
  complete-suite verification.
- The first permissions test exposed `0777` because Vitest inherited Windows
  `TEMP` and created its fixture on DrvFS. Explicit chmod could not repair that
  filesystem. Production now rejects such storage, and the valid fixture uses
  Linux `/tmp`, where `0700/0600` is enforced.
- One mobile stream mock returned synchronous `cancel`; it was corrected to the
  real promise contract.
- One JSON assertion inspected escaped outer text; it now parses the envelope.
- The first multi-file compatibility patch had invalid patch syntax and was
  reapplied as bounded hunks.

No model, external network, VPS, GPU, APK build, clinical data, personal file,
approval or execution was used.
