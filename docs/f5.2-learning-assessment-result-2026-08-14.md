# F5.2 learning assessment support

Date: 2026-08-14

EGO's existing assessment/mastery endpoint now accepts an optional BCP47 language, passes it through the provider-neutral grader and declares it in first-run and idempotent responses. The deterministic provider returns Spanish assessment feedback for `es-*`, enabling a network-free consistency test.

Privacy review found that attempt records retained raw learner responses. Local and Firestore persistence now store `response_count` and the pre-existing response digest instead. A regression test submits a unique private answer through the real local endpoint, parses the durable state and proves that the marker is absent while count, language, score and replay remain correct.

Retained development findings:

- an endpoint test initially expected Spanish prose from a fake provider whose fixed output was English; prose validation moved to the deterministic-provider test and the endpoint validates the declared tag;
- `npm run typecheck` failed because no such script exists; `node_modules/.bin/tsc --noEmit` passed;
- the first privacy test searched compact JSON in an indented state file; structured JSON inspection replaced it;
- one intermediate run logged that WebSocket port 24678 was busy; the final full run did not reproduce the warning.

Final source-tree evidence: 34 tests passed, one intentional cloud test skipped, and direct TypeScript compilation passed. The Nigma isolated golden path then graded three `es-MX` answers, updated mastery, replayed stably and proved the answer markers absent from EGO durable state. No external model, network, cloud, VPS or GPU was used.

Implementation commit `0fec362` was created on the existing `codex/runtime-hardening` checkout. Review showed that local and remote `main` were a strict ancestor by 14 commits, so GitHub `main` was advanced non-forcibly to this commit. A no-hardlink clone passes the same 34 tests with one cloud skip and TypeScript checking. During verification, Windows' npm shim could not locate WSL Node; invoking Vitest and TypeScript directly with the installed Node 22 binary passed and did not require a source or dependency change.
