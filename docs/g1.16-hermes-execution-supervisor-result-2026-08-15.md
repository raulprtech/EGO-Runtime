# G1.16 — Hermes execution supervisor

## Outcome

The replaceable Hermes sidecar now operates the separate G1.15 execution
authority. Approval remains one terminal action and execution remains another.
After EGO verifies the approval, a v3 binding retains only the execution phrase
hash and expiry. A later exact human turn can be scanned once or supervised
until it produces a terminal host-run record.

No ARIA source, Hermes source or real G1.14 plan changed. The package completed
an isolated HTTP golden with contractual Nigma and Hermes boundaries plus the
real EGO host-run and deterministic runtime.

## Binding and commands

`nigma.hermes-conversation-binding/v3` adds:

- explicit `execution=null` before execution;
- execution phrase SHA-256 and expiry only after verified approval;
- terminal message hash, host-run ID/status and execution-record digest after
  success;
- state transition `pending → recorded → executed`.

The standalone CLI adds:

- `execute-scan`: one bounded observation;
- `execute-watch`: restart-safe polling with the same transient-error budget
  as approval supervision.

Historical v1/v2 bindings remain verifiable. They cannot execute because they
lack a G1.15 authorization.

## Enforcement

The execution watcher requires:

1. v3 binding with a recorded approval and unexpired execution authorization;
2. the same sealed Hermes profile and conversation;
3. a later human `user` turn, excluding baseline and approval message hashes;
4. exact phrase hash with no prefix, suffix or normalization;
5. one candidate only;
6. an EGO terminal record matching conversation/message, approval ID/digest and
   observation time.

The sidecar atomically writes a `0600` executed binding. Replaying that file
returns `already_executed` without reading Hermes or contacting EGO.

## Isolated golden

The golden used owner-only temporary storage, an HTTP control-plane contract,
EGO's real API and host-run loop, the credential-free deterministic provider
and Hermes message fixtures. It observed:

- approvals posted: 1;
- runtime invocations requested: 1;
- deterministic executions completed: 1;
- receipts posted: 1;
- ARIA-compatible events: 2 (approval and terminal execution);
- replay calls after binding restart: 0;
- duplicate invocations/receipts: 0;
- raw execution phrase, session and message IDs in binding: 0;
- binding mode: `0600`.

The first valid human approval still produced zero invocations and receipts.
Only the second exact turn crossed the execution boundary.

## Retained failures and repairs

1. The first focused run had one obsolete assertion expecting a v2 binding.
   It was updated to the intentional v3 contract.
2. `jq` was unavailable while inspecting the tracked handoff fixture. Direct
   bounded file reading replaced it; no dependency was installed.
3. The first golden used historical fixed approval times and failed correctly
   with `NIGMA_HUMAN_APPROVAL_EXPIRY_INVALID`. Dynamic bounded test times
   repaired the fixture without relaxing production checks.
4. The second golden completed execution but its assertion assumed execution
   would sort before approval while the synthetic turn clock was slightly
   ahead of the host clock. The test now proves the exact two-event set without
   imposing ordering under simulated clocks.
5. Vite reported its development WebSocket port already occupied during the
   first two golden attempts. The HTTP golden remained isolated; the warning
   disappeared on the passing attempt and required no product change.
6. A combined documentation patch applied README/decision hunks but missed the
   guide because its wrapped context differed. A second broad guide patch also
   missed one contextual line. Small exact hunks completed the guide without
   changing code.

## Remaining boundary

G1.17 should deploy the built v3 sidecar against fresh isolated processes and
the real Hermes `aria` profile, but still use a harmless deterministic task.
Only after that checkpoint should the owner be asked to send the second phrase
from the real ARIA app. Login, VPS and mobile changes remain unnecessary.
