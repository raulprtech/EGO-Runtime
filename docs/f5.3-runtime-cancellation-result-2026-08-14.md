# F5.3 cooperative runtime cancellation

EGO local mode now accepts a bounded Nigma cancellation identity on the
existing authenticated cancel route. It records the ID and digest, lets the
active coordinator observe `JOB_CANCELLED` at its next lease checkpoint,
deletes partial artifact files and repository records, and persists structured
rollback evidence before publishing a terminal receipt.

Public status is `cancelling` while rollback is incomplete. The Nigma receipt
endpoint returns `NIGMA_CANCELLATION_NOT_DRAINED` during that interval. A
terminal cancelled receipt contains no generated artifacts, links to
`nigma-cancellation://<id>` and includes `rollback.performed=true`. Exact
cancellation retry returns the same durable state.

The deterministic provider has a test-only, bounded delay switch so the local
suite can reliably interrupt the planner after a partial concept artifact. It
is disabled by default and capped at five seconds.

Evidence: the focused Nigma handoff suite passed 4/4, the complete EGO suite
passed 36 tests with one intentional cloud skip, TypeScript passed, and Nigma's
real-process golden proved timeout, explicit cancellation, artifact cleanup,
receipt acceptance and restart replay. No external model, network, cloud, GPU
or VPS was used.

Retained findings: the first test exposed a duplicate `rollback: null` that
overrode new evidence; it was removed. Windows Node could not load Linux
Rollup, so tests used the already-installed Linux Node. Early golden attempts
exposed a completion race and a too-short cancellation HTTP timeout; the test
window and operation-specific timeout were corrected. Review then added the
explicit non-terminal `cancelling` projection so a drain timeout cannot claim
cleanup prematurely.

Cloud cooperative cancellation is not implemented. The route returns
`CANCELLATION_COOPERATIVE_CLOUD_NOT_IMPLEMENTED` before state mutation; a
future distributed design must combine durable worker acknowledgement, lease
fencing and GCS/Firestore cleanup.
