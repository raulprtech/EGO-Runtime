# Turn-based audio protocol

A client can implement one audio conversation turn with two provider-neutral endpoints.

```text
recorded audio
  -> POST /v1/runtime/transcriptions
  -> normalized text
  -> application or learning workflow
  -> response text
  -> POST /v1/runtime/speech
  -> WAV or PCM response
  -> playback
```

## Client sequence

1. Record a complete user utterance.
2. Send its binary bytes to `POST /v1/runtime/transcriptions`.
3. Use the returned `text` as input to the relevant application or learning operation.
4. Take the resulting response text and send it to `POST /v1/runtime/speech`.
5. Read audio metadata headers and play the binary body.
6. Cancel either HTTP request if the user interrupts the turn.

Transcription and synthesis correlation IDs should be generated by the client. They are not durable idempotency keys.

## Browser example

```ts
const transcriptResponse = await fetch(
  runtimeUrl + '/v1/runtime/transcriptions?language=es-MX',
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer ' + token,
      'Content-Type': recordedBlob.type,
      'X-Transcription-Id': turnId + '_input',
    },
    body: recordedBlob,
  },
);
const { text } = await transcriptResponse.json();

const replyText = await getApplicationReply(text);

const speechResponse = await fetch(runtimeUrl + '/v1/runtime/speech', {
  method: 'POST',
  headers: {
    Authorization: 'Bearer ' + token,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    speech_id: turnId + '_output',
    text: replyText,
    language: 'es-MX',
    format: 'wav',
  }),
});
const audioUrl = URL.createObjectURL(await speechResponse.blob());
await new Audio(audioUrl).play();
URL.revokeObjectURL(audioUrl);
```

This version waits for each completed transcription and synthesis response. The provider ports remain reusable if a future protocol adds streaming.
