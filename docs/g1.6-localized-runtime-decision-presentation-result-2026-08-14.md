# G1.6 — localized runtime-decision presentation

Date: 2026-08-14.

## Outcome

EGO now renders a verified G1.5 runtime explanation in `es-MX` or `en-US` as
`nigma.host-runtime-decision-presentation/v1`. The bounded projection contains
a title, selected/runner-up summary, up to three advantages, up to three
tradeoffs, localized reason text and an explicit disclaimer.

The object is always `informational_only`, `approval_granted=false` and
`execution_performed=false`. It links the exact source explanation ID/digest
and has its own canonical SHA-256 and content-derived ID.

`presentation_locale` is a host-only request preference. EGO validates it and
removes it before forwarding objective/material metadata to Nigma. The locale
enters the host preparation identity, so two languages are distinct views of
one unchanged Nigma plan. It never enters selection, approval or execution
authority. Fallback requests retain an empty body and may select the view with
`X-Presentation-Locale`; omission defaults to `es-MX`.

## Cross-process evidence

One real Nigma process and a temporary EGO on loopback port 3001 received two
requests with the same idempotency key and identical forwarded payload. The
Spanish and English results retained:

- plan `003b46af-da42-4b9f-8892-9380e5056a11`;
- selection `3ab84c7f-d93a-4ae5-9fd3-9a1af33993ea`;
- source explanation `runtime-decision-explanation-071fbf61d4caad82`;
- EGO 91.29%, Hermes 68.62%, margin 22.67 points;
- reliability +26.00, latency +0.17 and cost -3.50 points.

They produced distinct host preparation IDs and presentation IDs/digests. An
independent TypeScript recomputation validated both presentation digests.
Spanish used decimal commas and English decimal points. Neither response
approved or executed. The isolated EGO was stopped and port 3000 was untouched.

## Validation

- focused preparation/fallback tests: 8/8;
- complete EGO suite: 44/44 plus one intentional cloud skip;
- TypeScript: clean;
- Vite and server production bundles: passed;
- external model, external network, cloud, VPS, GPU, ARIA changes and clinical
  data: zero.

## Retained failures and repairs

- The first implementation forwarded locale into Nigma context. Review found
  that changing presentation language would then affect plan idempotency. The
  field was removed from the upstream schema/payload before the golden test.
- `bubblewrap` was unavailable, so approved interactive patches were used.
- `npm` resolved to a Windows Hermes shim without WSL Node. The installed Linux
  Node ran tests, TypeScript and Vite without installing dependencies.
- The combined validation reached esbuild after all earlier checks passed, but
  its script launcher could not find `/usr/bin/env node`. The direct Linux
  esbuild binary completed the server bundle in 13 ms.
- A whitespace-only residue remained in Nigma after reverting the first design;
  it was restored exactly before the real-process test.

This layer explains an already verified deterministic decision. It is not a
translation service for arbitrary text, a scoring authority or an approval
channel.
