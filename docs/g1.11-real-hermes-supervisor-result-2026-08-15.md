# G1.11 — real Hermes profile contract and local supervisor

Date: 2026-08-15.

## Outcome

The Hermes decision sidecar now probes the authenticated
`hermes.api_server.capabilities` contract, binds the exact profile and contract
digest into a v2 owner-only record, and requests message history with ARIA's
real `limit=10000&order=oldest&profile=aria` shape. Profile substitution,
missing bearer auth and incompatible session capabilities fail closed.

`watch` provides restart-safe local supervision. It polls within operator-set
bounds, retries only transport/timeout/429/5xx failures up to a fixed budget,
and stops on structural or authority errors. It persists only recorded or
expired terminal state. Restarting either state makes no upstream call. Direct
`scan` also seals v2 expiry before reading Hermes. No command can execute a
plan.

The production build now includes a dependency-bundled CommonJS sidecar that
can run beside loopback-only Windows Hermes while EGO/Nigma remain in WSL or
another replaceable host. ARIA/HermesMobile and Hermes source are unchanged.

## Retained failures and repairs

1. The first v2 run left all five G1.10 tests without a required contract
   digest and changed the expected query URL. Fixtures were migrated explicitly
   rather than weakening v2.
2. The first CLI patch left the capability import at end-of-file, causing a
   TypeScript syntax error. It was moved into the import block.
3. Configuration normalization retained EGO tokens at runtime but narrowed them
   out of its inferred type. Returning both fields explicitly repaired the
   compile-time boundary.
4. The first PowerShell restart command allowed Bash to expand `$p`, so Hermes
   never ran. A single-quoted PowerShell block repaired transport.
5. Restarting the wrong default profile triggered Hermes' interactive service
   installer and a Startup fallback. The correct `-p aria` gateway was started;
   the unintended default gateway and only its new persistence files were then
   removed with Hermes' own stop/uninstall commands.
6. WSL could not reach Windows `127.0.0.1:8642` although Windows health was 200.
   The sidecar was bundled to run beside Hermes instead of weakening URL policy.
7. The first ESM bundle failed on `dotenv`'s dynamic `require("fs")`. A CommonJS
   dependency bundle repaired Windows execution.
8. PowerShell did not relay direct child stdout, and two `WSLENV` attempts did
   not propagate the doctor variables. The final check kept secrets in the
   PowerShell process, redirected only sanitized JSON to temporary files, read
   it back and deleted the files immediately.

## Remaining boundary

The actual approval-writing `watch` path still requires EGO and Nigma to be
running with their independent credentials and an owner-generated v2 binding.
G1.11 intentionally did not synthesize another human approval. A later
end-to-end ARIA session should use this real supervisor and stop again at the
owner decision before any separately authorized execution.
